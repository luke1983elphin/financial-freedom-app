# Browser-Local Privacy Boundary

- Core plan data is stored in this browser on this device and is not automatically available on another device.
- A complete backup or Weekly Plan backup is a downloaded file controlled by the user; initiating a download does not prove the file was retained safely.
- Removing direct identifiers from a reduced summary does not by itself guarantee anonymity.
- No claim is made that no data ever leaves the device: static hosting receives ordinary request metadata and downloaded/printed data leaves app memory under user control.
- Both AI endpoints are disabled for this release. `AI_INSIGHTS_SERVER_ENABLED` and `PAYSLIP_EXTRACT_SERVER_ENABLED` accept only the exact string `true`; missing, false and invalid values cannot enable them. An additional code-level `AI_RELEASE_READY = false` lock prevents enablement even with flags and an API key. Disabled POST requests return a generic 503 before body access or network calls; coaching availability reports false. The browser omits the payslip file picker and returns before FileReader; coaching remains unavailable. Manual entry and calculations remain local and available.

Local security boundary: same-origin executing JavaScript can access `localStorage`; local storage is not encrypted storage and is not server-side secure storage; browser or script compromise may expose it; and clearing browser/site data can remove it. Processing location, provider-log retention and provider-deletion behavior depend on the deployed providers and must be confirmed before public release.

Privacy and Terms remain drafts pending professional Australian legal/regulatory review.

## Upload path audit — 19 October 2026

The dormant browser implementation accepts PDF/JPEG/PNG/WebP, caps files at 2.5 MiB, reads the **original** into a base64 data URL and posts it with MIME and filename to `/api/payslip-extract`. It does not extract or redact locally. The server caps the JSON envelope at 4 MiB and decoded file at 2.5 MiB. Images are sent in full to OpenAI Responses. PDFs are copied to OpenAI Files (`purpose=user_data`), then referenced in Responses. Neither path writes a local temporary file. Browser state holds the extracted amounts in memory until confirmation; confirmed values become ordinary plan data.

Responses uses `store: false`, 500 output tokens and a capped 30-second generation timeout. File upload and deletion have separate 10/5-second timeouts. A `finally` block attempts deletion after success, rejection, malformed output and generation timeout. Cleanup remains best effort: a network failure, rejected deletion, unknown file ID after an interrupted upload or process termination can leave a provider file behind. This is an **enablement blocker**, not a deletion guarantee. Provider/hosting retention and request-body logging must be audited in the deployed configuration. The handlers do not log bodies, documents, extracted fields or provider error payloads.

Instructions telling a model not to return identifiers restrict its output; they do **not** redact TFNs, bank details, names or other identifiers from transmitted input. `store: false` is not a promise of zero provider retention.

## Dependencies before any enablement

1. Decide whether AI is private operator access, public anonymous access or signed-in access. No account system has been added. The dormant server policy supports a private operator bearer token of at least 32 characters, compared using fixed-length hashes and timing-safe comparison. It must never be embedded in the public app. An Origin allowlist is a browser request check, **not authentication**. A public product needs a separately reviewed access/abuse design.
2. Provision and validate shared storage only after owner approval. The dormant policy uses an HTTPS Redis REST endpoint with atomic `EVAL`/`INCR`/`EXPIRE`: a global budget of 20 requests per fixed 3,600-second window starting with the first request across both routes and all instances, no in-memory fallback. Each accepted request makes at most one generation call. Configure `AI_ALLOWED_ORIGINS` as comma-separated exact HTTPS origins, `AI_PRIVATE_ACCESS_TOKEN`, `AI_LIMIT_REDIS_REST_URL` and `AI_LIMIT_REDIS_REST_TOKEN`. Missing or unavailable storage fails closed. Use a separate database for previews; validate concurrent exhaustion, expiry, storage eviction/persistence and operational alerts before enabling. No storage or paid service was enabled here. REST command format: [official Redis REST documentation](https://upstash.com/docs/redis/features/restapi).
3. Present active consent **before each upload**, naming OpenAI and explaining precisely what will leave the device, purpose, retention/deletion limits and identifiers. Obtain and review actual project/service configuration and contractual terms before stating any processing country. No location is asserted here.
4. Prefer local extraction into a strict numeric field allowlist, with human review before transmission; assess local PDF text extraction and OCR for scanned images. Test rotated/multi-page scans, low contrast, split labels, year-to-date versus period amounts, negative deductions, encrypted PDFs, hidden text and malicious documents. Confidence checks and TFN/bank-account detectors are imperfect. On ambiguity or failure, require manual entry; **never silently upload the original**. If raster redaction is considered, prove removal of underlying text, metadata and hidden layers and require preview. No such minimisation pipeline is implemented in this release.
5. Replace provider-file handling or implement reliable expiry/reconciliation with bounded retries and safe operational metadata. Re-test cleanup failures and process termination without recording personal content.
6. Review disclosure, provider terms, security and Australian privacy obligations with appropriate advisers; consent wording alone is not a legal-compliance assessment. Only after these dependencies and end-to-end tests pass should a reviewed code change lift the release lock and enable the corresponding UI.


## Evidence follow-up

Neither route implements per-IP limiting. The shared global budget is not a per-IP or sliding-window limiter. All Redis/provider checks are isolated mocks; no deployed infrastructure has been validated. Before activation, resolve the access and abuse-control design, including the per-IP requirement, and follow the deliberate source-lock, UI-lock and per-route flag sequence in [RELEASE-EVIDENCE-2026-10-19.md](RELEASE-EVIDENCE-2026-10-19.md).
