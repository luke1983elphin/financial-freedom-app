# Financial-model audit before Monte Carlo

Audit date: 13 November 2026. Repository: `luke1983elphin/financial-freedom-app`.
Audited latest `main`: `6f3dbf83cc744e765eddf6244313635ea357bc9a`, fetched before creating `audit/financial-model-before-monte-carlo`.

## Assessment

**The financial model is not ready for user-facing Monte Carlo simulation.** There are confirmed deterministic defects in tax funding, property-debt reporting and return selection, plus unresolved return conventions and unsupported tax treatments. Randomising these calculations would generate precise-looking probabilities around biased or incomplete cashflows. Existing deterministic comparisons remain useful within their stated scope; passing regression tests does not establish financial correctness.

This PR is an audit and proposed correction plan. No financial engine, tax configuration, defaults, protected hash, golden fixture or financial UI calculation has been changed. `vercel.json` disables automatic Git deployments specifically for this audit branch so creating the requested Draft PR does not request a preview deployment. No merge or deployment is authorised by this report.

The independent executable audit covers **48 synthetic household scenarios and 99 checks**: **36 households match every expectation; 12 contain at least one discrepancy or expose a limitation**. These are purposive cases, not a representative population sample or a model accuracy percentage. Some comparisons deliberately test an effective-annual or gross-return interpretation that the product must resolve; those are distinguished from unconditional arithmetic defects below.

Read [household-results.md](household-results.md) for every expected/actual/delta, [household-results.json](household-results.json) for all inputs and source hashes, [SOURCES.md](SOURCES.md) for evidence qualifications, [VERIFICATION.md](VERIFICATION.md) for execution evidence, and [USER-TESTING-PLAN.md](USER-TESTING-PLAN.md) for the proposed 16-household study. No household study has been conducted.

## Scope and independence

Reviewed the active main calculator (`calculator.js`), detailed retirement engine (`semiRetirementProjection.js`), retirement adapter (`semiRetirementUi.js`), investment income generation, asset/debt mapping, financial-year configuration, pension/SAPTO estimator (`agePensionEstimate.js`), inflation/display conversion (`dollar-basis.js`), central assumption descriptions, and existing report warnings. `app.js` delegates current plan calculations through the compatibility adapter to `FFSCalculator`; it does not use the separate illustrative TypeScript dashboard as the financial authority. `lib/calculations.ts` was inspected as a separate implementation; this report does not certify it as equivalent to the active Australian-tax engine.

The new oracle does not import expected numbers from existing regression tests or golden fixtures. It uses independently transcribed tax equations, government HELP examples, compound-interest and loan-annuity identities, economic return conservation and the dated pension schedule. Production functions supply only **actuals**. Fresh full inputs and reproducible outputs accompany the report. No private user data, account access or financial documents were used.

Matching amounts normally allow 2 cents for currency arithmetic; the 12-month loan identity allows 5 cents, the multi-year retirement identity 10 cents, the capital target 20 cents, and the independent tax-settlement example 50 cents. Those tolerances account for monthly cent rounding; none explains the material discrepancies. The oracle records all expected and actual values, including failures. Its exit code means the evidence run completed and every discrepancy has a finding ID, **not** that the model passed.

Source access has material limits. Current resident tax, HELP, SG and contribution-cap content was retrieved from the ATO; the deeming determination and SAPTO regulations were retrieved from legislation.gov.au. Services Australia returned 503 and DSS returned 403. Several ATO pages returned 404 or an outage page with HTTP 200. These were not treated as verified guidance. Pension maximums, free areas, supplement tax components and some tax concessions therefore remain conditional on the repository's prior dated register. A fresh qualified policy review is a readiness gate, not an implied completed check.

## What the default returns actually do

| Path | Default and timing | Tax treatment | Fee treatment | Audit conclusion |
| --- | --- | --- | --- | --- |
| Main accumulation, non-super | 7% divided by 12, compounded monthly; monthly contributions earn immediately | Legacy retained return has no earnings-tax haircut. Separately entered income is taxed. Explicit holding yield is taxed through household income; unrealised growth is not taxed and sales CGT is absent | No automatic fee deduction | Mechanically a retained return before any separately modelled income tax; no reliable blanket label of “after tax” |
| Main accumulation, super | 6.5% divided by 12, compounded monthly | Employer/additional concessional contributions receive a 15% contribution-tax deduction. Investment earnings receive no further tax deduction | No automatic fee deduction | Entered return is credited in full; it must already include earnings tax and costs if intended as a net assumption |
| Detailed retirement, non-super | 7% annual rate on opening balance plus half net movement; explicit holdings separate cash yield and retained growth | Explicit yield/entered income is ordinary taxable income. Aggregate return is not itself taxed; no realised CGT model. Tax funding fails in the zero-cash case F08 | Annual fee rate on the same midpoint balance, default 0% | Gross versus net convention must be explicit; entering a net-of-fee return and a fee also deducts that fee twice |
| Detailed retirement, super | New draft starts at 6.5% before full retirement and **5.5% afterwards**, not 6.5% throughout | 15% contributions tax, no separate earnings tax; access is an assumed scenario age | Explicit annual fee on midpoint balance, default 0% | Retired employment phase is not proof that assets entered a tax-exempt pension account; the 1-point reduction is an assumption, not a tax calculation |
| Simple sustainability illustration | Uses the investment return for the combined pot (or a configured investment-weighted variant) | No separate personal-income/CGT model | No separate fee model | Can apply 7% to super expected to earn 6.5%; see F07 |

**Neither 7% nor 6.5% is automatically converted from gross to net of earnings taxes and fees.** A 15% contribution-tax deduction is not a 15% deduction from every year's super return. It would also be wrong to “fix” this by subtracting 15% from all super returns: effective fund tax depends on earnings composition, CGT concessions, expenses and account phase. A net-of-fund-tax assumption can be legitimate, but its provenance and fee scope must be documented and consistent across engines.

Nominal and real dollars are separate from gross/net tax treatment. The return assumptions are nominal. Real return is `(1 + nominal return) / (1 + inflation) - 1`, not a second nominal return stream. At 7% and 2.5%, this is about 4.39% before other modelled costs.

### Financial impact interpretation

F02 is not proof that a nominal APR implementation is intrinsically wrong: `(1 + .07/12)^12 - 1 = 7.2290%`, while detailed annual no-flow return is 7%. The defect is unresolved terminology and inconsistent cross-engine treatment of the same assumption. Ignoring flows/rounding, $500k over 30 years differs by about **$252,121** at 7% and **$188,716** at 6.5% between monthly nominal compounding and effective annual compounding.

For F01, a separate sensitivity example demonstrates materiality without asserting a universal super tax rate: $500k at an effective annual 6.5% for 30 years versus `6.5% × 85% − 0.5%` leaves roughly **$1.13m** difference. Actual fund tax and costs require a documented source and may already be reflected in a quoted return. Charging them again to an already net return would understate balances instead.

F03's $15k is an economic-growth/income illustration error in the stated overlapping cases. It is not automatically a $15k portfolio increase: the effect on cash, affordable contributions and balances depends on reinvestment, ownership and tax. Conversely, an independent second investment genuinely can produce additional income; the model needs to establish that it is separate before excluding it.

F08 is more serious than a missing optional tax feature: H47 calculates the tax and then loses its cash effect. A household can appear fully funded while retaining money required to pay a known liability. Its ordinary income tax and Medicare check matches the independent oracle; the funding check fails. That is a conservation error even when the return definition is accepted as given.

## Domain reconciliation

### Australian personal tax

H01–H09 independently check current household income and ordinary resident income tax, LITO and individual Medicare across nil income, the tax-free threshold, phase-in, bracket boundaries and two earners. The 2026–27 15% first taxable band and later 30%/37%/45% bands match the fetched ATO table. Ordinary rates do not include MLS. H10/H11 independently reproduce ATO HELP repayment-income examples ($2,527.80 and $10,276.99); H12 checks repayment capped at the $1,000 actual debt balance. H13 checks the $3,200 personal tax saving and $8,500 net contribution on $10k extra concessional super at $100k salary.

The ordinary Medicare phase-in checks use the configured $28,011 threshold; they establish arithmetic under that schedule. Current family/pensioner thresholds were not independently revalidated in this audit. Medicare family reductions, SAPTO Medicare concessions, medical/residency exemptions, HELP indexation, detailed franking/CGT and specialist tax treatment remain outside the verified scope. MLS code distinguishes household threshold income, person surcharge base and hospital-cover days; boundary/partial-year cases remain covered by existing regression rather than a new independent tax-year certification here. Unknown cover status must not be read as a confirmed zero liability.

The main calculator's current-year assumptions are fixed at 2026–27. Detailed retirement uses the financial year starting on 1 July of each calendar label, changes to the enacted first-band 14% in 2027–28, then holds the latest supported rules; it does not forecast bracket indexation. That is an explicit fiscal-drag assumption, not an entitlement forecast. Separately distinguish future known law, held prior settings, and estimated policy, rather than treating all parameters in a supported year as newly verified.

### Investments and double counting

H17/H18 pass the core explicit-return identity: $35k total = $20k capital growth + $15k yield. Cash treatment retains $20k and pays $15k; reinvest treatment retains $35k and pays no cash. Both recognise $15k taxable income once. A linked dividend reference does not generate a second stream. Monthly accumulation uses increasing holdings and contributions, so its first-year totals need not equal the simple opening-value annual preview.

H16/H19 show that legacy/unlinked records bypass that protection. Portfolio returns also do not automatically model realised capital gains, capital losses, CGT discounts/cost basis, turnover, foreign withholding, investment-bond taxation or instrument-specific distributions. Treating all income yield as ordinary income is a simplifying assumption. A 7% retained return with no stated income yield does not establish that no tax is payable. Cash, offsets and debt-netted portfolio mappings also require an explicit return scope: debt interest is a financing cost, not grounds to earn equity-like returns only on net assets without a documented convention.

### Superannuation

The fetched ATO schedule supports 12% SG, annual maximum contribution base $270,830 and a $32,500 concessional cap in 2026–27. H01–H09/H13 check ordinary SG and contribution-tax arithmetic; H14 exposes omitted Division 293. Main projection contributions are spread monthly and detailed retirement uses midpoint timing. They are approximations, not a reconstruction of actual payday cashflows.

H26 correctly excludes a 55-year-old partner's $400k super while including the 62-year-old's $300k. H29 cannot fund age-59 spending from restricted super and reports $30k required unmet spending; H30 correctly uses $30k super after exhausting $10k liquid assets at assumed access age 60. Legal conditions of release, preservation histories, age-65 unrestricted release, work tests, untaxed funds, transfer balance caps, pension minimums, tax-free/taxable account components and downsizer qualification are not independently determined. The adapter's automatic 6.5%→5.5% return switch (H46) follows full retirement, not a verified pension conversion.

### Property, debt and offsets

H22 separates $18k gross property appreciation from current cash and reproduces omitted forecast debt. H23/H24 show $22k rent before interest or $7k after $15k interest each leaves $1k after $6k principal; interest is not deducted twice in these tested linked cases. H25 independently confirms first-month interest of $1,250 and the 12-month annuity balance for a $300k mortgage with $50k offset at 6% and $2k/month payments.

Detailed retirement schedules loans, separately records interest/principal, excludes active offset cash from normal investment earnings, and keeps property equity outside spendable retirement cash unless an event realises it. Main accumulation remains a simpler fixed-income/expense/non-mortgage-cashflow path; it must not be interpreted as the same lifetime funding engine. Payoff, balloon, capitalised-interest and offset transitions are extensively regression-tested, but only H25 and the specified rental cases have new independent debt expectations in this audit.

Property appreciation is not rent or a liquid draw. Detailed rent cash grows with CPI; taxable rent can have a separate path. Sale CGT, detailed stamp duty, depreciation schedules, sale timing/liquidity, mixed-security debt, refinancing and future rental tax are incomplete. Taxable rental losses can reduce modelled taxable income where entered correctly, but the app does not establish deductibility or infer taxable profit from rent/expenses. One-off income is generally assumed untaxed; users must not enter taxable sale proceeds as if that settled the tax.

### Retirement funding and timing

H28 independently reconciles $1m less $40k spending, with midpoint earnings of $68,600 and fees of $9,800, to $1,018,800. H29/H30 test inaccessible-super boundaries and the funding waterfall; H47 disproves full tax funding in the no-cash reinvestment case. There is no single assured wealth path shared by accumulation, FI targets, simple sustainability and detailed retirement. Do not publish a probability using one path as if it validated all four.

Detailed rows use age **at the start** of the annual interval and include the row whose starting age equals the selected end age; its closing balance is after another full year. Main accumulation uses end-year ages. These are documented conventions, but align interval endpoints before comparing ending wealth or reporting “through age 90.” Detailed horizon follows the younger partner and can extend beyond the older partner's chosen age. Death, survivorship, bereavement pension treatment, inheritance and stochastic longevity are not modelled. Simple sustainability additionally uses combined-pot assumptions and cannot establish tax-aware retirement feasibility.

### Age Pension and SAPTO

H32–H36 independently calculate maximums, assets taper, income taper and one-eligible-partner outcomes under the repository's 20 September/1 July 2026 schedule; H37 excludes the principal residence and younger partner accumulation super and applies lower-tier deeming; H42 exercises pension→SAPTO→funding with no private assets. H48 independently derives the single SAPTO threshold `ceil(18,200 + (445 + 2,230)/0.15) = 36,034` from the statute and verifies nil income tax at $30k. This is distinct from ordinary LITO; replacing the statutory $445 constant with current LITO would be wrong.

The independently retrieved deeming determination confirms 1.75%/3.75% from 20 September 2026. Other pension constants could not be independently revalidated online during this run. Do not call the full schedule current-certified. Annual assessment is a dated domestic estimate: both means tests are recalculated, only eligible partners are paid, and future maxima/thresholds use annual CPI rather than the statutory CPI/PBLCI/wages schedule. Energy Supplement, taper percentages, Work Bonus and deeming rates stay fixed. Negative CPI does not lower pension parameters. Rental assessment, home exemptions and linked-debt security assumptions may differ in specialist circumstances. Residency, Work Bonus banking/opening credit, fortnightly earnings changes, overseas rates, rent assistance, illness separation, trusts/businesses and grandfathered products require separate treatment. Under-67 super is assumed accumulation unless the scenario option indicates an income stream.

### Inflation and dollar basis

H27 checks $80k today spending inflated over 10 years and the corresponding 4% capital target; it also checks exact nominal→today-dollar reversal. H31 checks two annual spending withdrawals with 2.5% CPI. H45 checks deflation in spending. Deflation need not lower pension thresholds under the estimator's policy proxy, so these paths intentionally diverge. Nominal projection and display-only deflation are correctly separated in the tested examples.

Wage growth is used in detailed retirement/saved retirement timing, while legacy accumulation keeps income and ordinary living costs fixed. Property growth, investment income, taxable rent and CPI have different assumptions; applying CPI globally to every balance would be incorrect. Inflation variability, wage correlation and policy indexation must be explicit before stochastic modelling. A 4% target is a capital heuristic; it is not the detailed funding rule, a success probability or an assurance of a sustainable withdrawal rate.

## Practical correction sequence and Monte Carlo entry gates

1. **Resolve conventions before code changes.** Record whether every return is effective annual or nominal APR, whether fund tax/fees are already included, whether yield is part of total return, how taxable sales work, and what dollar/interval basis a result uses. Select one authoritative lifetime funding engine and document the other screens' scope.
2. **Correct F08 first**, with explicit signed household cash and tax liabilities. Add independent cases for one/both owners with reinvested income, a working spouse, negative cashflow, reserve restrictions and insufficient liquid assets. Every liability must be paid, carried or reported unfunded.
3. Correct F04/F07 and reconcile canonical assets/debts, accessible versus restricted super, initial balances, return sources, age endpoints and reported net worth. Replace ambiguous double-count paths in F03 without erasing genuine second-source income.
4. Establish supported tax/account scope for F05/F06/F09, complete source revalidation and obtain qualified Australian tax/super/pension review. If a feature remains unsupported, exclude affected probability claims and make the limitation visible at input/result time.
5. Extend explicit holdings to downside returns (F10), verify total = retained + paid yield under losses, handle fees/depletion/recovery, and define CGT/realisation strategy. Simulations must not truncate negative returns to make validation pass.
6. Re-run this independent ledger and the unchanged regressions, plus property sale, offset depletion, mixed-age access, pension boundary and multi-year tax-funding conservation cases. Require no unexplained material variance and agreement on the economic source of every return/income amount.
7. Complete the proposed household study after corrected deterministic examples are available. Resolve material misunderstanding about net returns, pension entitlement, inaccessible wealth and probability wording.
8. Only then design a stochastic layer: documented return/inflation distributions and calibration dates; income versus growth/fees/tax split; asset/inflation correlations; bad-sequence and prolonged-loss paths; seeded reproducibility; convergence error; explicit horizon, mortality and success/shortfall definitions; and deterministic zero-volatility equivalence. Do not infer these from the current 7%/6.5% point defaults.

A research-only simulation design document can be prepared now. User-facing probability outputs should remain blocked until these financial gates are met. This audit does not implement Monte Carlo or authorise protected calculation changes.
