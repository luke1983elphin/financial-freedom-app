## Retirement correction

The engine withdrew opening balances before crediting mid-year investment earnings. In an underfunded year those earnings survived the withdrawal pass. The exact-zero milestone consequently lagged the first shortfall. The mobile portfolio-withdrawal card also displayed accessible withdrawals alone, omitting super withdrawals.

After ordinary return calculations, a settlement pass now consumes available accessible balances above reserves, then eligible super, before finalising unmet spending. It preserves the existing return basis, contribution rules, access checks and withdrawal preference. It updates annual totals, reconciliation and person closing snapshots together. No arbitrary depletion threshold is used. Restricted super and reserved cash remain restricted, with explicit retained-fund explanations; the milestone refers to available funding.

The synthetic ages 83–90 fixture starts with $10,000 accessible investments, $170,000 super, $70,000 annual spending and 5% returns. It produces the same defect pattern: shortfall in 2068, but old exhaustion in 2072. The correction moves exhaustion from age 89 to age 85 without hard-coding either age. Earlier fully funded years are unchanged.

The $32.92 increase in lifetime shortfall removes later returns on the already-consumed residual. Shortfall still begins in 2068. Complete before/after traces with every requested field are in `retirement-age-83-90.csv` in the evidence archive and `before.json` / `after.json`.

Retained assets use closing asset and liability rows at the corrected exhaustion year, or projection end if funding survives. Stable asset IDs and unambiguous income/loan relationships map debt. Ambiguous debt produces unknown debt/equity rather than a guessed outright status. Zero ownership/value and sold assets are excluded. Existing downsizing replacement rows are respected. Property remains outside withdrawals unless an existing explicit event releases proceeds. The fixture retains a home worth $1,092,727 with no linked debt at age 85. Cards include name, type, ownership, value, debt, equity and status, with neutral later-sale/estate wording.

## FI and cashflow findings — requested items 1–31

1. **Current/future FI inconsistency:** `futureYouPreview` skipped current-age projection rows and built a manual fallback from investments, legacy offset and missing-row super. Future years used broader canonical property-inclusive rows. The projection started at year one. A canonical year-zero wealth row and shared age selector now remove that discontinuity.
2. **Observed $150,000:** the old fallback can produce $100,000 shares plus $50,000 crypto when legacy offset is zero, despite a structured offset record. This is a demonstrated composition, not verification of unavailable personal inputs.
3. **Observed $693,858:** exact decomposition is unavailable. Old future rows included financial investments, canonical offset, net investment-property equity and eligible super, with growth/contributions/debt movements. The controlled fixture instead proves current $690,000 and next-year $715,880.04 Total FI Wealth.
4. **Old property treatment:** net equity, not gross market value, entered the primary FI numerator. It is now separately named Investment Property Equity.
5. **Old offset treatment:** future rows read canonical offset; the fallback read legacy offset. Offset was therefore omitted at current age only when the legacy mirror was stale or missing. The new selector uses canonical offset at both ages.
6. **Definitions:** Accessible FI Assets are liquid financial investments plus offset and model-accessible super, net of relevant investment debt. Investment Property Equity is value less attributable debt. Total FI Wealth is their sum. Home Equity is separate. Inaccessible super is separately tracked. Unsold property is never available withdrawal cash.
7. **Financial Freedom percentage:** accessible assets divided by the existing required-capital measure. Property equity no longer inflates the primary funding percentage. Growth, inflation, safe-withdrawal-rate and access assumptions are preserved. Help text and version make the semantic correction explicit.
8. **Shared helper:** `calculator.js:calculateNetFiAssetSummary` accepts the canonical plan, age and optional projected investment/property/super values. It returns the named components and compatible funding aliases. `calculatePlan` adds `fiWealth` and `fiWealthProjection`; `selectFiWealthAtAge` selects current/future values, preserving valid zeroes.
9. **Live Summary path:** plan → `calculatePlan` → canonical income, expense, rental and loan helpers → `householdCashflow` → `app.js:renderSetupSummary`. Rendering reads calculated values rather than reconstructing cashflow.
10. **Calculation sources:** `normalisedIncomeItems`, `incomeCashAnnualAmount`, `incomeTaxableAnnualAmount`, rental cashflow summary, `canonicalLiabilityItems`, `getAnnualLoanBreakdown`, `householdLoanCashflow`, existing tax/expense helpers and `calculatePlan`; detailed retirement inputs are adapted in `semiRetirementUi.js`.
11. **Omitted repayments:** the old main summary omitted standalone non-home loans. Rental-linked treatment existed but could omit unmatched loans; after-interest rent also made the displayed repayment total mean only the remaining cash deduction. The new calculation counts each canonical loan once and distinguishes full payments from remaining deductions.
12. **Loan treatment:** home payments use existing amortisation/offset mechanics; rental payments use stable linked loan breakdowns; other loans and cards enter once. STSL remains in required tax/income deductions, not duplicated as another household loan payment. Inactive/deleted loans are filtered and IDs deduplicated. Unlinked rental loans remain payable and produce a warning.
13. **Rental cash:** cash fields, not taxable profit, feed household cash income. Missing cash information does not create invented rent.
14. **Rental expenses:** operating expenses reduce gross rental cash under existing ownership/frequency handling. Already-net cash is not reduced twice.
15. **Rental interest:** before-interest rent deducts full loan payments; after-interest rent deducts principal only. The summary separately exposes interest already included in net rent.
16. **Rental principal:** the existing loan breakdown supplies principal; it reduces spendable cash but does not become a tax deduction.
17. **Annual Income:** household cash income, comprising employment and other cash income plus net rental cash, before household tax and remaining debt deductions. Fixture: $100,000 salary + $20,000 rental cash = $120,000. The label now says household cash income (net rent).
18. **Net Income:** cash income less calculated tax, Medicare/MLS and STSL. Taxable rental input remains separate. Fixture taxable income $105,000; income tax $22,020 + Medicare $2,100 + MLS $0 + STSL $0 = $24,120; net cash income $95,880. Existing tax formulas and simplified dividend treatment are unchanged.
19. **Living Expenses:** active household living-expense records annualised through existing frequency helpers, excluding separately modelled loans and discretionary investment contributions. Fixture $40,000.
20. **Annual Surplus:** $120,000 − $24,120 − $40,000 − $30,000 home payments − $18,000 rental payments = $7,880, before discretionary investing. With after-interest rent, only the remaining loan cash deduction is subtracted here.
21. **Cashflow used to invest:** actual affordable discretionary investment, capped to nonnegative surplus after configured extra-super cash allocation. Fixture $7,880; remaining cash $0. Negative current surplus funds no new discretionary investment.
22. **Configured/affordable/actual:** configured $12,000 remains visible and stored; affordable $7,880; actual $7,880. The current contribution base used in the accumulation projection is the affordable amount. Extra-super assumptions were not redesigned.
23. **Rental reconciliation:** fixture gross rent $30,000 × 100% ownership − $10,000 operating expenses = $20,000 before-interest cash. Zero-rate loan: interest $0, principal $18,000, full payments $18,000, resulting household rental cash $2,000. Taxable rental result is a separate explicit $5,000 assumption, demonstrating that taxable profit is not substituted for cash. Separate tests cover nonzero interest, interest-only, after-interest and ownership cases.
24. **Cross-screen consistency:** Dashboard/Future You/current FI/report FI fields use the shared funding/wealth definitions; Live Summary uses canonical cashflow. The detailed retirement adapter uses the same cash-income distinction and canonical active loan inputs. A deterministic first-year reconciliation passes. This is not a claim that the two existing projection engines have identical lifetime outputs.
25. **Intentional differences:** detailed retirement net cash already deducts rental debt: $77,880 versus main $95,880 before loan deductions. Subtracting home payments $30,000 and living $40,000 yields $7,880 in both. Monthly contribution rounding gives $7,880.04 in the annual accumulation row. Browser readiness requires positive return/inflation assumptions, so UI screenshots use 5% returns/2.5% inflation while arithmetic evidence uses zero growth. Current cash/balance components match; future progress denominators differ accordingly. Historical saved snapshots are not rewritten.

31. **Separate modelling issues:** the simpler accumulation model still reinvests legacy mortgage payments after payoff without a full future-year affordability recalculation; it uses household super at person-one access age, whereas detailed retirement models each person. Its broader net-worth path retains legacy mirror/timing conventions, and its home-equity forecast uses the plan-level home-growth assumption. The detailed adapter's all-empty legacy fallback can still revive stale legacy debt if all structured records are inactive. These pre-existing edge cases were not silently redesigned; mixed-age, stale-legacy and future affordability scenarios should receive dedicated follow-up. Current canonical FI/cashflow tests do not imply these broader limitations are resolved.
